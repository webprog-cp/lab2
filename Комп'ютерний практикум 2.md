**Комп’ютерний практикум 2\. Робота з постійним сховищем,  валідація вхідних даних** 

**Мета** 

Отримати навички роботи з технологією ORM для постійного збереження  сутностей REST API у базі даних, а також використання шаблонів проєктування  «Репозиторій» та «Data Transfer Object». 

**Завдання** 

1\. Замінити у програмному забезпеченні, розробленому в ході виконання  першої роботи комп’ютерного практикуму, тимчасове зберігання даних на  постійне у базі даних. 

2\. Додати валідацію вхідних даних. 

**Вимоги до програмного забезпечення** 

1\. Для реалізації програмного забезпечення в ході виконання комп’ютерного  практикуму може використовуватися будь-який стек (мова програмування,  вебфреймворк і так далі) технологій. 

2\. Для постійного зберігання сутностей може використовуватися будь-яка база  даних. 

3\. Для роботи з базою даних необхідно використовувати ORM та шаблон  проєктування «Репозиторій». 

4\. Для отримання екземплярів репозиторіїв для роботи з БД необхідно  використовувати IoC-контейнер для ін’єкції залежностей. 

5\. REST API замість передачі та отримання об’єктів-сутностей, що зберігаються  у БД, повинне використовувати окремі DTO. 

6\. Вхідні DTO повинні валідуватися на предмет коректності (за допомогою  бібліотеки FluentValidation або аналога для обраного стеку технологій). 

**Вимоги до звіту з роботи комп’ютерного практикуму** 

Звіт з роботи комп’ютерного практикуму повинен містити: 

1\. Титульну сторінку.  
2\. Постановку завдання: предметна галузь з першої роботи комп’ютерного  практикуму, короткий опис ідентифікованих у предметній галузі сутностей,  розширений описом доданих валідаційних правил. 

3\. Код розробленого програмного забезпечення. 

4\. Знімки екрану з прикладами результатів роботи валідації DTO під час  виклику методів реалізованого REST API (вхідні дані обираються на розсуд  студента). 

5\. Висновки.
